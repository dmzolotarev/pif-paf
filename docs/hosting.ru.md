# Хостинг своей игры

[English](hosting.md) | [Русский](hosting.ru.md)

Основной вариант — Cloudflare Workers (приложение), D1 (состояние) и R2 (фото). Следуйте шагам в своём аккаунте. Условия и тарифы сервисов проверяйте в их актуальной документации.

## 1. Подготовка

Установите Node.js 22.18+ и клонируйте репозиторий. Выполните:

```sh
npm ci
npx wrangler login
npx wrangler d1 create pif-paf-db
npx wrangler r2 bucket create pif-paf-photos
```

Cloudflare может потребовать включить R2 в аккаунте. Созданный бакет не нужно делать публичным: фото отдаёт приложение.

В `wrangler.jsonc` замените фиктивный `database_id` на ID из ответа `d1 create`. Если меняли имена ресурсов, обновите `database_name`, `bucket_name` и имя Worker. Имена bindings `DB`, `PHOTOS`, `ASSETS` сохраните.

В шаблоне нет account ID, домена или чужого database ID. Нулевой UUID нужен для локальной разработки и не является production-базой.

## 2. База и первая публикация

```sh
npm run db:migrate:remote
npm run deploy
```

Миграции применяются до публикации новой версии. `deploy` не применяет их автоматически. Cloudflare Vite plugin записывает конфигурацию собранного Worker; `wrangler deploy` использует результат сборки.

Первый запуск создаст пустую игру со случайным регистрационным кодом. До настройки production-секретов вход организатора и регистрация не будут готовы — это ожидаемо.

## 3. Секреты

```sh
npx wrangler secret put ORGANIZER_SECRET
npx wrangler secret put PLAYER_AUTH_SECRET
```

Введите **разные длинные случайные значения**. Первое — пароль организатора. Второе подписывает сессии и PIN-хеши игроков; сохраните его для будущих обновлений и восстановления из резервной копии.

Для генерации локальных значений есть `npm run secrets:generate`: значения будут в игнорируемом `.dev.vars`. Этот файл не загружается как production-секрет автоматически.

Если нужна генерация газетных заметок:

```sh
npx wrangler secret put OPENAI_API_KEY
```

Модель выбирается в админке. Без ключа работает шаблонная газета. Ключ никогда не отправляется браузеру. Используйте собственный API-проект; доступ и расходы определяются его настройками.

Никакого Cron, отдельного Worker-планировщика или webhook настраивать не нужно.

## 4. Первый вход

Откройте адрес `workers.dev`, полученный при публикации, и `/admin`. Введите `ORGANIZER_SECRET`, задайте название, группы и правила. Сохраните их до регистрации участников. Затем разошлите общую ссылку и код либо создайте общую пригласительную ссылку без кода.

## 5. Собственный домен

В Cloudflare откройте Worker → Settings → Domains & Routes → добавьте Custom Domain. Используйте домен, которым управляете. Сначала проверьте вход и фото по новому адресу, затем раздавайте его участникам.

Сессии привязаны к домену. После смены адреса участники входят заново по имени и PIN.

## Обновление

Сделайте резервную копию, загрузите новую версию исходников, выполните `npm ci`, `npm run check`, `npm run db:migrate:remote`, затем `npm run deploy`. Не меняйте `PLAYER_AUTH_SECRET` при обычном обновлении: иначе перестанут подходить существующие PIN и сессии.

В репозитории закреплены совместно проверенные версии инструментов. Обновление Vinext/Cloudflare Vite plugin выполняйте отдельно от обновления правил игры и проверяйте сквозными тестами.

## Резервные копии

Экспорт D1:

```sh
npx wrangler d1 export DB --remote --output game-backup.sql
```

Храните экспорт вне Git: он содержит имена, историю, PIN-хеши и диагностику статей. Для полного восстановления нужны также объекты R2 и тот же `PLAYER_AUTH_SECRET`. Экспорт SQL сам по себе не включает фотографии. Резервное копирование R2 выполняется отдельно через инструменты R2/S3.

## Отключение

Кнопка «Пауза» блокирует игровые действия, но сайт продолжает открываться. Чтобы закрыть доступ к самой установке, настройте ограничение доступа в Cloudflare либо удалите её Worker через панель. Оставленные D1/R2 позволяют восстановить игру. Удаление базы или бакета — отдельное необратимое действие; оно не требуется для остановки сайта.

## Другие платформы

Текущая версия использует Cloudflare bindings напрямую. Инструкция для VPS/Docker, Vercel или обычного статического хостинга не заявляется рабочим способом запуска. Для них понадобятся другие адаптеры базы и хранения фото.

Справка: [Cloudflare Vite plugin](https://developers.cloudflare.com/workers/vite-plugin/), [D1 migrations](https://developers.cloudflare.com/d1/reference/migrations/), [R2](https://developers.cloudflare.com/r2/).
