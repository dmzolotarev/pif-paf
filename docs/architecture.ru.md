# Архитектура

[English](architecture.md) | [Русский](architecture.ru.md)

React 19 + TypeScript, Vinext/Vite, Cloudflare Worker, D1 и R2. Один инстанс обслуживает одну игру с техническим ID `default`.

- `app/GameApp.tsx` — загрузка состояния, вкладки и действия текущего игрока.
- `app/components/` — вход/анкета, участники, редакционные показания, итоги.
- `app/admin/` — управление игрой; настройки мероприятия и журналиста выделены в отдельные компоненты.
- `app/api/` — серверные проверки доступа и игровые операции.
- `lib/game-engine.ts` — чистые функции жеребьёвки и проверки единого цикла.
- `lib/game.ts` — bindings, сессии, PIN и общие серверные функции.
- `lib/mutation.ts` — защита атомарных изменений цикла от устаревшей ревизии.
- `lib/settings.ts` — настройки и их валидация; `settings-store.ts` читает их из D1.
- `lib/journalist*.ts`, `article-generation.ts` — форматы, промпты, генерация, fallback и диагностика.
- `lib/finale.ts`, `final-stats.ts` — выпуск материалов при финале и подсчёт итогов.
- `db/schema.ts`, `drizzle/` — описание таблиц и чистые миграции новых установок.
- `worker/index.ts`, `vite.config.ts`, `wrangler.jsonc` — самостоятельный Cloudflare runtime.

## Данные

`games` хранит настройки и ревизию. `players` — профиль, фото-ключ, статус и текущую цель. `events` — выбытие с прежними связями, показаниями и статьёй. `article_generations` — административную диагностику. `game_mutations` — уникальные номера изменений, которые нельзя повторно применить.

В D1 лежат ключи объектов фотографий; сами фото — в непубличном R2-бакете. Локальные ресурсы хранятся в `.wrangler/`, не входят в Git и не переносятся при деплое автоматически.

## Инварианты

При двух и более активных игроках у каждого одна жертва и один предшественник; все образуют единый цикл. Выбывший не имеет цели. У последнего победителя цель отсутствует. Группы на жеребьёвку не влияют.

Изменения цикла выполняются через D1 `batch`. Первая операция резервирует следующую ревизию в `game_mutations`; конфликт откатывает batch целиком. Ревизии не сбрасываются при новом раунде. События хранят прежние связи для отката последнего выбытия.

Клиент не вычисляет новые цели. API состояния отдаёт только цель текущего игрока; полные связи доступны организатору и раскрываются в итогах завершённой игры.

## Публикация

`publish_at` — момент, после которого статья попадает в ленту. На чтении дополнительно проверяется ручное одобрение. Cron и внешнего сервиса нет. Открытый клиент опрашивает сервер каждые 12 секунд.

После приёма показаний HTTP-запрос заканчивается; генерация запускается через `after()`. Если она не удалась, доступен шаблон. Организатор видит статус и может повторить генерацию. Долговременной очереди с гарантированными повторными попытками нет.

Финал снимает задержки и ограничения публикации для действующих событий. Лидерборд считает только успешные убийства; разоблачение не засчитывает киллеру убийство.
